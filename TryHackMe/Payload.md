# 🤖 Payload - TryHackMe Writeup

## Objective

Investigate a suspected AI supply-chain compromise by analyzing deployment logs, reverse engineering a malicious machine learning model, examining network evidence, and recovering the hidden campaign flag.

---

# Task 1 - Deployment Log Analysis

The first step was to inspect the deployment log to understand when the production model was replaced.

```bash
cat /opt/supply-chain/incident/logs/deployment.log
```

The log showed that the original model was replaced by another model downloaded from a different Hugging Face organization.

### Question 1

**Which organization supplied the replacement model?**

The deployment log contained the following entry:

```text
Source: huggingface.co/trustworthy-ai-lab/code-review-bert-v2
```

### Answer

```text
trustworthy-ai-lab
```

---

### Question 2

**How many days passed before the SOC generated an alert?**

From the deployment log:

* Model deployed: **2024-01-26**
* SOC Alert: **2024-02-16**

Calculating the difference:

```text
21 days
```

### Answer

```text
21
```

# Task 2 - Reverse Engineering the Production Model

The production model is stored as a Python Pickle file.

Since Pickle files may execute arbitrary code when loaded, they should **never** be opened using `pickle.load()` during an investigation.

Instead, inspect the serialized instructions safely using:

```bash
python3 -m pickletools /opt/supply-chain/incident/models/production_model.pkl
```

The output revealed several important instructions.

---

### Question 3

**Which Python function executes the malicious payload?**

The decompiled output showed:

```text
system
```

This indicates the attacker used the operating system's command execution function.

### Answer

```text
system
```

# Task 4 - Inspecting the Candidate Model

The engineering team had prepared another model (`candidate_model.h5`) but had not deployed it yet.

Instead of manually examining the file, the room provides an inspection tool.

Run:

```bash
python3 /opt/supply-chain/tools/inspect_h5_model.py \
/opt/supply-chain/incident/models/candidate_model.h5
```

The script analyzes the model architecture and highlights suspicious layers.

---

# Task 5 - Recovering the Flag

Neither the production model nor the beacon log contains the complete flag individually.

The attacker intentionally split the campaign identifier between two different artefacts.

From the beacon log, the flag prefix was recovered.

The remaining portion was obtained from the candidate model.

Combining both parts produced the complete campaign identifier.

### Flag

```text
THM{b4ckd00r_1n_pl41n_s1ght}
```

# Key Takeaways

* Never deserialize untrusted Pickle files using `pickle.load()`.
* Deployment logs can reveal unauthorized software replacements.
* `pickletools` allows safe inspection of serialized Python objects.
* Machine learning models can contain executable payloads.
* Correlating logs and artifacts is often necessary during incident response.
* Supply-chain attacks can target AI models in addition to traditional software.

---

# Conclusion

The Payload room demonstrates how attackers can compromise an AI supply chain by replacing a legitimate machine learning model with a malicious one. Through deployment log analysis, safe model inspection, and network log correlation, it was possible to identify the malicious behavior, reconstruct the attack timeline, and recover the campaign flag.
